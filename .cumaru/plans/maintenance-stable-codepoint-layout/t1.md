# T1 — Slot-anchored layout in config + codepoints

## What to do

Replace the positional dials with slot arithmetic in `config.py`, and give
`codepoints.py` a way to turn a declared slot into a theme base.

## Context

Only two codepoints per sprite are ever mapped: `layout.icon(i)` at block `+0`
and `layout.sprite_full(i)` at block `+SPRITE_CP_OFF`. The 320-wide stride is
left over from the per-cell mosaic renderer dropped in
`maintenance-drop-mosaic`; nothing has used the headroom since.

## Implementation

- `CP_STRIDE` `0x140` → `0x10`, `SPRITE_CP_OFF` `0x110` → `0x8`.
- Add `THEME_SPAN = 0x400` — codepoints reserved per theme slot (63 sprites plus
  the blank at `0x10` stride).
- Add `theme_base(slot)` to `codepoints.py`, returning `CP_BASE + slot * THEME_SPAN`.
- Keep `find_free_base` for the skeleton-collision check, but it no longer picks
  the layout.

## Done when

- [x] `theme_base(0) == CP_BASE` and `theme_base(1) - theme_base(0) == THEME_SPAN`.
- [x] `CodepointLayout` unchanged in shape — it still takes a base and a sprite count.
