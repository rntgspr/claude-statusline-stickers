# T3 — Build assigns from slots and validates

## What to do

Delete the cursor walk in `build.build()`. Each theme's base comes from its
declared slot; conflicts are build errors.

## Context

The cursor walk is the defect: `cursor += (len(theme.sprites) + 1) * CP_STRIDE`
makes every base depend on the sprite counts of every theme before it.

## Implementation

- Probes keep slot 0: `probe_layout = CodepointLayout(theme_base(0), 0)`.
- Per theme: `layout = CodepointLayout(theme_base(theme.codepoint_slot), len(theme.sprites))`.
- Validate before rendering anything, so a bad config fails fast:
  - slot is `None` → `SystemExit` naming the theme;
  - slot already claimed → `SystemExit` naming both themes;
  - slot 0 → `SystemExit` (reserved for probes);
  - `(len(sprites) + 1) * CP_STRIDE > THEME_SPAN` → `SystemExit` naming the theme
    and both counts.
- Keep the existing `agentNames` collision check as-is.
- Report the slot in the build's summary line.

## Done when

- [x] `stickers build` succeeds for all six themes.
- [x] A duplicated slot, a missing slot, and an over-full theme each fail with a
      named error.
