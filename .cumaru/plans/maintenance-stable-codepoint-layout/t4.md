# T4 — Verify stability across theme add/remove

## What to do

Build the full theme set, build a subset, and diff the resulting cmaps for the
themes present in both.

## Context

This is the regression that matters: it is exactly what the old layout failed,
and it is cheap to check because `STICKERS_VER` pins the build for reproducibility.

## Implementation

- Build all six themes; record `codepoint -> glyph name` for every
  `sprite.<theme>.*` mapping.
- Build again with one theme's directory withheld; record the same.
- Assert every shared glyph name sits at an identical codepoint.
- Repeat the old positional layout on the same inputs to show it fails the check.

## Done when

- [x] Every glyph common to both builds keeps its codepoint.
- [x] The same assertion fails against the pre-change layout.
